# Contributing to Tukar QR

Thank you for helping improve [Tukar QR](https://tukarqr.my). This project is a
fully client-side Next.js app for regenerating DuitNow QR images in the browser.

## Before you start

- Read the [Code of Conduct](CODE_OF_CONDUCT.md).
- Search [existing issues](https://github.com/shahrulestar/qrkita/issues) to
  avoid duplicate work.
- For large changes, open an issue first to discuss the approach.

## Development setup

Requirements: Node.js 20+ and npm.

```bash
git clone https://github.com/shahrulestar/qrkita.git
cd qrkita
npm install
npm run dev
```

The app runs at [http://localhost:3000](http://localhost:3000).

Optional environment variables are documented in `.env.example`. None are
required for local development.

## Project notes

- **Static export only** — no backend, database, or server runtime.
- **Stack** — Next.js 16 App Router, React 19, TypeScript, Tailwind CSS 4,
  shadcn/ui.
- **Package manager** — npm (`package-lock.json`). Do not commit other lockfiles.
- **Agent context** — see [AGENTS.md](AGENTS.md) for automation and CI notes.

## Making changes

1. Create a branch from `main` (for example `fix/upload-validation` or
   `feat/batch-export`).
2. Keep changes focused and match existing code style and conventions.
3. Prefer extending existing components and utilities over adding parallel
   implementations.
4. Do not commit secrets (`.env`, tokens, webhook URLs).

## Checks before opening a PR

Run these from the project root:

```bash
npm run lint
npm run test
npm run build
```

All three should pass. The static export output is generated by `npm run build`.

## Pull requests

- Use a clear title and fill in the [pull request template](.github/pull_request_template.md).
- Link related issues (`Fixes #123` or `Relates to #123`).
- Include screenshots or screen recordings for UI changes.
- Describe how you tested on desktop and, when relevant, mobile viewports.

## Reporting bugs

Use the [bug report issue template](.github/ISSUE_TEMPLATE/bug_report.yml) and
include steps to reproduce, expected vs actual behavior, browser/device details,
and sample images only if you are comfortable sharing them publicly.

## Feature requests

Use the [feature request issue template](.github/ISSUE_TEMPLATE/feature_request.yml)
and explain the user problem, proposed solution, and alternatives considered.

## Questions

Open a [GitHub Discussion](https://github.com/shahrulestar/qrkita/discussions)
